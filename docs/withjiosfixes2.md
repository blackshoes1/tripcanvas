## 0. 이 문서를 읽는 방법

여섯 가지 중 **하나는 회귀 버그**(5번)이고 나머지는 없던 것을 더한다. 크기가 제각각이라
**작고 독립적인 것부터** 넣고, 서로 기다리지 않는다.

지켜야 할 것:

1. **엔진은 하나다.** 판단 로직(`adaptive.js`·`lib.js`·`collab.js`)을 Swift로 복제하지 않는다.
   앱은 `/api/v1`이 준 결과를 **그리기만** 한다. 필요한 값이 없으면 Swift에서 계산하지 말고 API에 노출한다.
2. **완료는 "실행 가능한 빌드 + 게이트 초록 + 실기기 확인 + 되돌릴 수 있음"이다.**
   `테스트 작성됨`과 `테스트 통과`를 섞지 않는다.
3. `main` 직접 푸시 금지. 브랜치 → PR → 필수 체크 통과 → merge.
4. ⚠️ **`next/src/**`를 바꿨으면 NAS에 따로 배포한다.** `main` 머지는 Vercel 정적 웹만 내보낸다.
   릴리스 체크리스트에 명령이 있다(2026-09-06에 이걸 잊어서 새 라우트가 404였다).

## A. 일정 탭 — 시간 칸이 줄바꿈된다 (회귀)

### 증상
📌 도착 고정인 장소에서 시간이 두 줄로 갈린다. 아이콘이 없는 줄(예상 도착)은 멀쩡하다.

### 원인
`SpotRow.timeColumn`이 `📌` + `09:30`을 **48pt 고정 폭**에 넣는다. 아이콘이 붙는 순간 넘친다.
(2026-09-06 PR4에서 들어간 것이다 — 시각 3종을 세기로 가르면서 아이콘을 시간과 같은 줄에 뒀다)

### 고칠 때 지킬 것
- **폭을 늘리는 것으로 끝내지 말 것.** 큰 글씨 설정(Dynamic Type)에서 다시 넘친다.
  아이콘과 시간을 같은 줄에 묶어야 하는지부터 다시 본다 — 아이콘을 시간 **위/아래**에 두거나,
  고정 폭 대신 내용에 맞춘 폭 + 최소 폭으로 두는 편이 안전하다.
- 시각 3종의 **세기 차이는 유지한다**: 📌 도착 고정(굵게) · 예상 도착(옅게) · ⚠️ 충돌(주황).
  이건 앱의 핵심 구분이라 없애면서 고치면 안 된다.
- 시간은 `monospacedDigit()`이라 자릿수가 흔들리지 않는다 — 그 성질을 잃지 않는다.

### 완료 기준
- [ ] 📌가 붙은 줄과 안 붙은 줄의 시간이 **같은 자리에서 시작**하고 줄바꿈이 없다
- [ ] 손쉬운 사용 → 글자 크기를 **가장 크게** 해도 줄이 깨지지 않는다(최소한 시간이 잘리지 않는다)
- [ ] 24시를 넘는 시각(`25:10`)도 한 줄에 들어간다

## B. 여행 목록 — 왼쪽으로 밀어 삭제

### ⚠️ 삭제와 나가기는 다른 일이다
**역할에 따라 동작이 갈린다.** 이걸 하나로 합치면 남의 여행을 지우거나, 내 여행에서 조용히 나가진다.

| 내 역할 | 밀었을 때 | 무엇을 부르나 |
|---|---|---|
| 소유자 | **삭제** | `DELETE /api/v1/trips/:id?expectedRevision=N` (tombstone) |
| EDITOR · VIEWER | **나가기** | `CollabService.leave(tripId:)` |

`TripSummary.role`로 판정한다. 웹은 이미 이 규칙이다 — `collab.js`의 `canDelete`/`canLeave`가
단일 출처이고, `CollabModel`에 복사본이 있다. **Swift에서 역할 조건을 새로 쓰지 말고 그걸 쓴다.**

### 지킬 것
- **되돌릴 수 없는 동작이므로 확인을 받는다.** 무엇이 사라지는지 말한다 —
  소유자는 "함께 보는 사람들에게서도 사라집니다", 멤버는 "내 목록에서만 사라집니다".
- 삭제는 `expectedRevision`이 필요하다(CAS). 목록의 `revision`을 그대로 보낸다.
  **409(다른 기기가 먼저 바꿈)면 조용히 넘기지 않는다** — 목록을 새로 불러오고 다시 묻는다.
- 실패하면 **행을 되돌린다.** 낙관적으로 지워 놓고 실패를 삼키면 다음 새로고침에 되살아난다.
- 오프라인이면 시도하지 않고 그렇게 말한다(목록은 캐시로 볼 수 있다).

### 완료 기준
- [ ] 소유자 여행은 삭제, 공유받은 여행은 나가기로 동작하고 **문구가 다르다**
- [ ] 확인 없이는 사라지지 않는다
- [ ] 실패(권한·409·네트워크)하면 행이 되돌아오고 이유가 보인다
- [ ] XCTest: 역할별로 어느 경로를 부르는지 · 실패 시 목록이 되돌아오는지

## C. 시작 전 여행 — D-day와 '여행 보기'

### 무엇을
여행이 **아직 시작되지 않았을 때** 지금 탭이 D-day를 먼저 보여 준다.

```
        D-12
   2026-10-01 출발
  ┌────────────────┐
  │    여행 보기     │
  └────────────────┘
```

**'여행 보기'를 누르면 평소의 지금 화면 내용이 나타난다.** 즉 D-day는 시작 전의 *기본* 화면이고,
지금 화면을 못 보게 막는 것이 아니다.

> ⚠️ **확인 필요**: "여행 보기"를 눌렀을 때 보이는 지금 화면은 **첫날 기준**으로 읽는다고 가정했다
> (`GET .../today?day=0`). 여행 기간 밖에는 '오늘'이 없어서 기준 날이 필요하다.
> 다른 뜻이었으면 알려 주세요.

### 지킬 것
- **D-day 계산을 Swift에서 하지 않는다.** 여행이 진행 중인지는 이미 서버가 정한다
  (`TripSummary.todayIndex`, `adaptive.js`의 `currentDayIndex`). 남은 날짜도 같은 규칙에서 나와야
  한다 — 서버가 안 주면 **계약에 더한다**(예: `daysUntilStart`). 앱이 `start`를 오늘과 비교해
  세면 시간대 때문에 웹과 하루가 어긋난다.
- **끝난 여행은 D-day가 아니다.** `todayIndex`가 -1인 경우는 시작 전과 끝난 뒤 둘 다다.
  둘을 구분해 다른 말을 한다(끝난 여행에 "D-12"가 뜨면 안 된다).
- **날짜 없는 여행**(`start`가 빈 문자열)은 셀 것이 없다 — D-day를 만들지 말고 다른 안내를 한다.
- 오늘이 출발일이면 여행이 시작된 것이다(`todayIndex >= 0`) — 이 화면이 나오지 않는다.
- 2026-09-06의 시작 화면 규칙(`TripHomeTab.initial`)과 **충돌하지 않는다**: 시작 전 여행은
  기본이 `일정` 탭이고, 이 화면은 사용자가 `지금`으로 옮겼을 때 보인다.

### 완료 기준
- [ ] 시작 전 여행의 지금 탭에 D-day와 출발일이 보이고, '여행 보기'로 평소 화면이 나온다
- [ ] 끝난 여행 · 날짜 없는 여행에 D-day가 뜨지 않는다
- [ ] D-day 숫자가 웹과 같다(시간대가 다른 여행에서 확인)
- [ ] XCTest: 시작 전/진행 중/끝난 뒤/날짜 없음 네 경우의 판정

## D. 지도 탭 — 동선 표시

### 지금
`MapEngineView`가 **핀만** 그린다. 두 엔진(Google Maps SDK·Kakao Maps SDK) 어디에도 선을 그리는
코드가 없다. 그래서 "이 날 어떻게 도느냐"가 지도에서 안 보인다.

### ⚠️ 먼저 정할 것 — 무엇을 그릴 수 있나
`GET /api/v1/trips/:id/days/:i`는 구간의 **분과 km는 주지만 경로 좌표열(path)은 주지 않는다.**
서버에는 구간 캐시가 없기 때문이다(`travelTimeSource: STRAIGHT_LINE_ESTIMATE`).

따라서 둘 중 하나다:

| 길 | 무엇 | 대가 |
|---|---|---|
| **직선으로 잇는다** | 장소 순서대로 직선. 작고 확실하다 | 실제 도로가 아니다 — **직선임을 화면이 말해야 한다**(웹은 점선으로 구분한다) |
| 실제 경로를 받는다 | 계약에 `path`(인코딩 폴리라인)를 더하고 서버가 라우팅 | 서버에 구간 캐시·라우팅 호출이 필요하다. 훨씬 크다 |

**직선부터 하는 것을 권한다.** 지금 없는 것은 "순서와 방향"이지 "도로 모양"이 아니다.
실제 경로는 별도 작업으로 두고, 그때 웹의 `legCache`·`routing.js`와 어떻게 한 소스로 만들지 정한다.

### 지킬 것
- **추정을 실측처럼 그리지 않는다.** 직선이면 점선으로, 그리고 한 번은 글로 말한다
  (웹이 자동 합성 구간을 점선으로 구분하는 것과 같은 이유).
- **좌표 없는 장소는 선에 넣지 않는다.** 응답의 `spotsWithoutLocation`이 몇 개인지 알려 주므로
  "위치 없는 장소 N곳은 지도에 없어요"를 계속 말한다(이미 있는 문구다).
- **숙소 복귀는 자동 합성 구간이다.** 그릴 거면 다른 선으로 — 사용자가 넣은 이동이 아니다.
  ⚠️ 마지막 날에는 아예 없다(서버가 주지 않는다).
- **렌터카 픽업·반납은 좌표가 없다.** 동선·지도에 넣지 않는다.
- 색은 일자 색을 따른다(웹과 같은 규칙). 두 엔진에서 같은 색·같은 두께로 보여야 한다.
- 국내는 Kakao, 해외는 Google — `MapEngineView`가 이미 고르고 있다. **선도 양쪽 다** 그려야 한다.

### 완료 기준
- [ ] 국내 여행(카카오)과 해외 여행(구글) 양쪽에서 선이 보인다
- [ ] 직선임이 화면에 드러난다
- [ ] 좌표 없는 장소가 선을 끊지 않고, 그 사실을 화면이 말한다
- [ ] 장소가 0곳·1곳인 날에 깨지지 않는다
- [ ] 일정을 바꾸면 선이 따라 바뀐다
