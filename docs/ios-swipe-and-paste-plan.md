## PR A — 행 스와이프 삭제 제거

**문제.** `TripPlanView`의 `.onDelete`가 스와이프 삭제를 계속 켠다. SwiftUI의 `onDelete`는
편집 모드 삭제와 **스와이프 삭제를 둘 다** 켜기 때문이다. 같은 행 위에서 가로 스와이프는
삭제가 이기므로 #208의 날짜 이동이 목록 행에서는 동작하지 않는다. 주석("편집 모드로 옮겼다")도
사실과 다르다 — #208에서 `.swipeActions`를 `.onDelete`로 바꾸며 잘못 적었다.

**할 일.**
- `.onDelete(perform:)`에 **편집 모드일 때만** 클로저를 넘기고 아닐 때는 `nil`을 넘긴다.
  `perform`이 옵셔널이라 `nil`이면 스와이프 삭제가 붙지 않는다.
- `@Environment(\.editMode)`로 판정한다. 오른쪽 위 `EditButton()`은 그대로 두고 편집 모드의
  ⊖ 삭제와 드래그 재정렬은 살린다.
- 틀린 주석을 고친다 — 왜 편집 모드에서만인지(가로 제스처를 날짜 이동이 쓴다).
- `.deleteDisabled(!model.canEdit)`은 유지. 보기 권한은 편집 모드에서도 못 지운다.

**검증.** 편집 모드 밖에서 행을 밀면 날이 넘어가고 삭제 버튼이 안 나온다 / 편집 모드에서는
⊖로 지워진다 / VIEWER는 못 지운다. ⚠️ 앞의 둘은 **기기에서만** 확인된다.

## PR B — 앞뒤 하루를 미리 받아 둔다

**문제.** 날을 옮기면 `selectedDay`의 `didSet`이 `loadPlan()`을 부르고, 그 날 계산이 없으면
디스크 캐시 → 없으면 서버를 기다린다. 스와이프가 아무리 부드러워도 넘어간 뒤 목록이 늦게
지어지면 튀는 것처럼 보인다.

**할 일.** `TripPlanViewModel`에 `prefetch(day:)`를 더한다.

- `loadPlan()`이 **성공한 뒤** `selectedDay±1`을 낮은 우선순위로 받는다.
- 현재 revision의 계산이 이미 있으면 건너뛴다.
- 진행 중인 날을 `Set<Int>`로 들고 있어 **같은 날을 두 번 받지 않는다**(빠르게 밀면 쌓인다).
- 받은 것은 `plansByDay`·`cachedAtByDay`·`attemptedDays`에 넣는다 — 그래야 넘어가는 순간
  `planAttempted(for:)`가 참이라 목록이 기다리지 않고 지어진다.
- ⚠️ **미리 받은 것이 지금 보는 날을 덮지 않게 한다.** prefetch는 자기 날짜에만 쓴다.
- ⚠️ **revision이 바뀌면 버린다.** 편집한 뒤의 옛 시각을 보여 주느니 다시 받는다.
- ⚠️ `scheduleLegRetry`는 미리 받은 날에 걸지 않는다. 보지도 않는 날 때문에 3초 뒤 재조회가
  도는 것은 배터리와 서버 낭비다. 그 날로 실제로 옮겼을 때 `loadPlan`이 건다.
- 서버 구간 채우기는 이미 `[day, day+1, day-1]`을 데운다(`route-deps.ts`) — 클라이언트 캐시만
  없던 것이라 이 PR로 짝이 맞는다.

**검증(XCTest로 가능하다).** 날짜별 `dayPlan` 호출을 세는 가짜 서비스로: 0일차를 열면 1일차도
받는다 / 1일차로 옮기면 다시 받지 않고 2일차만 새로 받는다 / 앞뒤로 빠르게 오가도 같은 날
요청이 두 번 나가지 않는다 / revision이 바뀌면 버린다 / 마지막 날에서 `day+1`을 요청하지 않는다.

## PR C — 새 여행 만들기 안에 붙여넣기

**문제.** 목록 `+` 메뉴에 `새 여행 만들기`와 `가진 일정 붙여넣기`가 따로 있다. 처음 온 사람은
둘 중 무엇이 자기 상황인지 메뉴를 열기 전에는 모른다.

**고른 길: 한 시트 안의 두 갈래.** `+`를 단일 버튼으로 되돌리고 `NewTripView` 맨 위에
`Picker`(`처음부터 만들기` / `가진 일정 붙여넣기`)를 둔다. 첫 진입이 한 걸음 짧아지고 두 길이
나란히 보인다.

- `PasteItineraryView`의 본문을 뷰 하나로 빼고 시트 껍데기는 바깥이 씌운다. 완료 콜백은 이미
  `(TripSummary) -> Void`라 그대로 쓴다.
- ⚠️ **시트를 닫으면서 다른 시트를 여는 길은 택하지 않았다** — SwiftUI에서 어긋나서 `onDismiss`
  대기 플래그로 한 박자 넘겨야 하는데, 그 함정을 감수할 값이 아니다.

**지킬 것.**
- 붙여넣기의 **미리보기 → 확인 → 저장** 순서를 건드리지 않는다.
- 두 길의 결과가 같아야 한다 — 만들어진 여행으로 바로 들어간다(`path = [created]`).
- 실패 문구는 각자 화면이 이미 들고 있다. 합치면서 잃지 않는다.
- **초대 링크로 참여**는 계정 메뉴에 그대로 둔다(만들기와 다른 일이다).

**검증.** `TripListRemovalTests`의 `FakeTrips`가 `createTrip(draft:)`와 `createTrip(document:)`를
이미 모사한다 — 두 갈래가 각각 맞는 쪽을 부르는지, 실패했을 때 유령 행이 안 남는지 확인한다.
⚠️ 시트 전환 자체는 XCTest로 못 본다.
