# iOS 여행 현장 UX 네 가지

## 80번 빌드 후속

- 원문 입력은 입력 중 공백·줄바꿈을 보존한다. 다른 선택지를 편집해도 확정 상태를 유지한다.
- 더 머물기 미리보기에서 revision 충돌·만료를 받으면 최신 일정으로 돌아간다. 적용 버튼은 `N분 더 머물기 적용`, 닫기는 `취소`다.
- `지금 → 일정에서 확인`은 해당 날짜·이름·revision을 함께 확인한다. 개인 선택 조회의 취소는 오류로 표시하지 않는다.
- 개인 선택은 같은 DB 트랜잭션에서 `DAILY_MOMENT_CHANGED` 신호를 발행한다. `id:0`은 활동 이력 번호가 아닌 무효화 신호다. 서버 안의 tripId/clientId/actorId만 사이드카에 보내고 사용자에게는 기존 권한 검사 후 tripId/kind/mine을 보낸다. 일정 revision은 바꾸지 않는다. 열린 화면만 소켓·30초 폴백을 사용하고 마지막 확인 시각을 표시한다.
- **안심 한 줄**: 공통 엔진이 실제 경로·현재 위치·남은 출발 여유를 확인한 경우만 제공한다. 미정 선택지·조정 필요·기간 밖은 제외한다. 60초가 지나거나 오프라인이면 재확인 안내로 바꾼다.
- **건네주기 카드**: 택시기사용은 목적지·주소, 예약 직원용은 예약 사실을 표시한다. 용도를 바꾸면 예약번호를 다시 숨긴다.
- **바로 고르기**: `지금`에서 두 장소의 사진·머무름·입력 비용·경로를 비교한다. `choice-comparison`은 인증·revision을 확인하는 읽기 전용 API다. 경로는 실제/추정을 구분하고 없는 값은 미정으로 표시한다. 선택은 기존 CAS 저장이며 서버 확인 후만 성공을 표시한다. 응답 유실은 최신 확인으로, 되돌리기는 저장된 revision으로만 수행한다.
- **내일 아침 30초**: 여행지 시각 18시 이후 다음 날이 있는 여행에서 첫 이동 출발 예상·체크아웃·예약·항공편·기기의 오프라인 사본 준비 상태를 표시한다. 저장된 다음 날 일정과 오프라인 준비 화면으로 연결한다. 알림을 새로 예약하거나 일정을 자동 변경하지 않는다.

이 후속은 서버/API를 먼저 배포한 뒤 iOS를 배포해야 한다. 구버전 서버에서 새 선택지 비교 경로를 받지 못하면 이동시간을 지어내지 않는다.

## 사용 흐름

- **조금 더 머물기**: 여행 당일 `지금`에서 머무는 중인 일반 장소 → 10/20/30분 → 예약 준비 여유·선택 장소 체류 감소·마지막 방문 종료 시각 확인 → 직접 적용. 계산은 `adaptive.js`, 저장은 기존 revision CAS다. 약속·꼭 가기·숙소는 줄이지 않는다. 미정 선택지와 따로 움직이는 구간이 남으면 자동 적용하지 않는다. 미확인 이동은 여유를 단정하지 않으며 합성 숙소 복귀는 종료 시각 문구에 포함하지 않는다.
- **직원에게 보여주기**: `지금`의 다음 장소, 일정 장소의 메뉴/편집기, 예약 상세에서 큰 글씨 화면을 연다. 장소/예약 편집기의 원문 입력에서 확인한 현지어 이름·주소·예약자명을 적는다. 예약번호는 직접 공개하고 앱을 벗어나거나 계정이 바뀌면 다시 숨긴다. 저장된 문서로 오프라인 열기가 가능하며 지도는 저장 좌표의 외부 링크다.
- **나중에 고르는 일정**: 장소 편집기에서 다른 선택지를 추가한다. 두 곳은 한 칸이며 처음 장소만 잠정 계산된다. 범위는 체류와 동일 조건의 입력 비용에 한하며 다른 경로 전체의 범위를 만들어내지 않는다. 화면에 계산 기준과 결정 시각을 표시하고 사용자가 고르면 다시 계산한다. 예약 연결/숙소는 기준점 손상을 막기 위해 묶을 수 없다.
- **각자 오늘 하나만**: `같이 짜기` 또는 `지금` → 날짜 → 본인이 원하는 기존 장소 하나 → 개인 선택 저장/거두기. 다른 사람의 선택은 바꿀 수 없다. 일정 조정·더 머물기 미리보기에서 영향을 받은 선택을 이름과 함께 보여준다. 개인 희망은 모두의 합의나 고정 예약으로 자동 승격하지 않는다.

## 저장 및 호환

- `spot.choice`는 기존 장소 안에 대안 하나만 보관한다. 선택은 원문 필드를 유지하는 기존 문서 저장을 사용한다. 구버전은 현재 장소를 읽고 중복 계산하지 않는다.
- `spot.staffShow` / `booking.staffShow`는 확인한 원문을 여행 문서에 보관한다. 번역·주소를 생성하지 않는다.
- `POST /api/v1/trips/:id/stay-extension/preview|apply`는 서버 시계·최신 revision·미리보기 결과 지문을 확인한다. 응답 유실 후 이전 revision으로 재전송해도 두 번 연장하지 않는다. 저장 완료를 확인하지 못하면 최신 일정 확인으로 돌아간다.
- `GET|PUT /api/v1/trips/:id/daily-moments`는 네이티브 COLLAB 저장소를 사용한다. 마이그레이션 `0018_daily_moments`는 `(여행, 날짜, 사용자)`별 선택을 별도 보관한다. 문서/멤버 행 잠금을 확인하고, 위치 인덱스 대신 장소 지문으로 추적한다. 같은 장소가 중복되거나 이름·위치가 달라지면 다시 고른다. 날짜 없는 여행에서 날짜/제목을 바꾸면 다시 확인해야 한다.
- 계정별 캐시와 늦은 응답 차단을 유지한다. 오프라인 쓰기를 성공으로 표시하지 않는다. 본 기능 구현 과정에서 실제 운영 여행 데이터를 만들거나 바꾸지 않는다.

## 검증

순수 계산·정규화·API·DB 권한/동시성·Swift 모델·합성 UI 흐름을 검증한다. 합성 UI는 `--ios-review-ui`에 `--review-stay`, `--review-staff`, `--review-choice`, `--review-moments`를 붙인다. 체류/선택/개인 희망 저장 실패도 별도 시나리오로 확인한다.

Windows의 `npm run verify:all`은 bash 미설치로 실행되지 않는다. Xcode/실제 PostgreSQL 검증은 기존 Linux/macOS CI 결과로 구분해서 기록한다. 실제 iPhone 사용성과 운영 저장 확인은 배포 후 별도다. 네이티브 API/DB를 먼저 배포·확인한 뒤 iOS 빌드를 배포해야 하며, 이 작업은 구현/PR 검증 범위다.
