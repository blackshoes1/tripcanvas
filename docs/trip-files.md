# 여행 음성 가이드와 티켓·문서

With J가 음성을 생성하지 않는다. 사용자가 만든 음성을 장소에 연결하고, PC·웹·iPhone과 여행 멤버 사이에서 같은 파일을 사용한다.

## 사용 흐름

- 웹 음성: 로그인한 여행의 장소에서 **음성 가이드**. 연결할 장소를 확인하고 파일을 여러 개 고른다. **이 기기에만 보관한 음성**으로 기존 기기 목록도 연다.
- 웹 문서: **☰ → 티켓·문서** 또는 **예약·결제 → 티켓·문서**.
- iOS 음성: 장소 상세 또는 **지금 → 음성 가이드**. 같은 여행·장소의 공유 목록을 연다.
- iOS 문서: **일정 메뉴 → 여행 티켓·문서** 또는 **더보기 → 여행 티켓·문서**.
- 업로드한 음성의 제목을 고치거나 **위로**를 눌러 재생 순서를 정한다. 관람 순서에 맞게 원하는 이야기를 직접 눌러 듣는다.
- **오프라인 저장**으로 해당 기기에 사본을 남긴다. 음성을 듣거나 문서를 열 때도 사본을 저장한다. 저장 성공 여부는 파일 옆에 표시한다.
- iOS 문서는 Quick Look으로 열고, 웹 문서는 파일로 내려받는다. 음성은 재생 위치를 기억한다.
- 공유 음성은 창을 닫고 지도를 열어도 재생을 이어간다. iOS는 배경 오디오·잠금 화면 재생 명령을 연결했다. 통화·헤드폰 분리는 일시정지한다. 실제 기기의 오디오·파일 제공자·잠금 화면 확인은 macOS 빌드와 별도로 필요하다.
- 기존 기기 전용 음성은 그대로 남는다. iOS의 **이 iPhone에만 보관한 음성**, 웹의 기존 음성 목록에서 연다. 공유를 원하면 원본 파일을 직접 선택한다.

## 저장과 권한

API는 NAS의 기존 PostgreSQL에 메타데이터와 파일 바이트(base64)를 함께 저장한다. 새 파일 저장 서비스나 공개 버킷 설정은 필요 없다. 기존 DB 백업에 포함된다. 파일은 여행 JSON·공유 링크·일정 내보내기에 들어가지 않아, 오래된 일정 저장이나 실행취소가 파일을 지우지 않는다.

목록·다운로드마다 로그인과 현재 여행 멤버 자격을 확인한다. OWNER·EDITOR가 업로드·제목 수정·순서 변경·삭제하고, VIEWER는 열기와 다운로드만 한다. 저장소는 여행 행과 멤버 행을 트랜잭션에서 잠가 권한 회수와 파일 처리가 엇갈리지 않게 한다. 공개 공유 링크의 사본에서는 파일을 열 수 없다.

기기 사본은 계정·여행별로 분리한다. 웹은 IndexedDB에 ArrayBuffer로, iOS는 Application Support에 파일 보호를 적용해 저장한다. 로그아웃·계정 전환은 재생을 중지한다. 이미 내려받은 사본을 원격으로 회수하지는 않는다. **기기의 사본 지우기**와 **공유 파일 삭제**는 서로 다른 동작이다.

## 지원 범위와 제한

| 종류 | 형식 | 파일당 크기 |
|---|---|---|
| 공유 음성 | MP3, M4A, WAV, OGG/OGA/Opus, FLAC | 25 MiB |
| 티켓·문서 | PDF, JPEG, PNG, WebP, UTF-8 TXT | 10 MiB |

여행당 최대 100개·총 200 MiB. 실제 음성 재생 지원은 브라우저·OS 코덱에 따른다. 서버는 확장자와 바이트의 형식 표식을 함께 확인한다. HTML·실행 파일·빈 파일·과대 요청은 거절한다. 문서는 첨부 다운로드로 응답하고 no-store·nosniff를 설정한다.

한 번에 20개까지 고르고 클라이언트가 하나씩 올린다. 서버 프로세스는 동시에 2개까지 업로드를 처리한다. 연결 실패·일시 오류만 최대 3회 재시도한다. 여행·장소·종류·SHA-256 해시가 같은 파일은 기존 항목을 돌려줘, 성공 응답을 놓쳐도 중복이 생기지 않는다. 실패한 파일명과 이유를 표시하며 파일을 다시 골라 재시도할 수 있다. 업로드 대기 파일 자체를 새로고침 후 자동 복구하지는 않는다.

일정의 장소 연결은 기존 음성 가이드와 같은 Google ID → Kakao ID → 좌표 → 도시·이름 순서다. 정렬이나 날짜 변경은 연결을 바꾸지 않는다. 장소의 ID·위치를 바꾸면 새 장소로 취급한다. 문서는 첫 버전에서 여행 전체에 첨부한다. 예약별 분류·OCR·도착 감지 자동 재생·음성 생성은 포함하지 않는다.

## 배포와 확인

아직 운영에 배포한 기능이 아니다. [NAS 릴리스](nas-release.md)의 **API 먼저** 규칙에 따라 서버·마이그레이션 PR을 먼저 배포하고 운영 revision을 확인한 뒤 웹·iOS를 배포한다. 마이그레이션은 Drizzle이 생성한 새 trip_files 테이블이다. 스키마 롤백은 하지 않고, 앱 이미지를 되돌려도 파일 테이블과 보관 파일은 남긴다.

API 테스트는 PGlite에서 권한·멤버 회수·중복·바이트 일치·종류·용량·메타데이터 변경·삭제를 검증한다. 브라우저 E2E는 테스트 서버 응답으로 PC 업로드→다른 브라우저 다운로드→오프라인 열기와 실제 WAV 재생을 확인한다. 이는 운영 NAS를 통한 실기기 동기화 검증과 구분한다.

검증 명령: 전체 npm run verify:all, API npx vitest run src/server/api/tripFileRoutes.test.ts (next/), 웹 npx playwright test e2e/trip-files.spec.js. Swift 캐시 테스트는 SharedTripFileStoreTests에 있다.
