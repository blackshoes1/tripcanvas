# With J 이야기 — 장소별 음성 해설

작성 2026-10-22. 상태: **설계 승인(2026-10-22) · 웹 1단계 구현 중**. 아래 '구현 메모'가 설계와 다른 점을 적는다.

## 무엇을 만드는가

With J가 미리 준비한 장소 해설을 일정의 장소에 **저절로** 붙인다. 사용자는 파일을 고르지 않는다.
세비야 대성당이 일정에 있으면 그 장소에 '🎧 With J 이야기'가 뜨고, 누르면 듣는다.

기존 '내 음성 파일 붙이기'(기기 전용·공유 업로드)와는 다른 기능이다. 그쪽은 사용자가 만든 파일이고,
이쪽은 With J가 쓰고 검수해 내보내는 콘텐츠다. 화면에서는 한 묶음(음성 가이드) 안에 두 칸으로 보인다:
위는 **With J 이야기**, 아래는 **내가 붙인 음성**.

첫 출시 콘텐츠(세비야 파일럿):

| 항목 | 종류 | 분량 |
|---|---|---|
| 세비야 | 도시 소개 | 2~3분 1편 |
| 스페인 광장 (Plaza de España, 세비야) | 장소 | 핵심 1~2분 + 더 듣기 |
| 레알 알카사르 (Real Alcázar, 세비야) | 장소 | 핵심 1~2분 + 더 듣기 |
| 세비야 대성당·히랄다 | 장소 + 관람 지점 | 기존 14곳 원고(01~12 기본, 13~14 선택) |

목소리: Google Cloud TTS Chirp 3 HD **Despina**, 쉼 추가 버전, 보통 속도(사용자 선택).

### 마요르카 (2026-10-31)

장소마다 4~8분짜리 한 편(`CORE`)이다. 세비야처럼 핵심·더 듣기로 나누지 않았다 — 오디오 가이드로 먼저 만든 원고를 그대로 실었다.

|---|---|---|---|
| 마요르카 섬의 역사 (`mallorca-island`) | 도시 소개(CITY) | 8분 37초 | 섬 안의 날 — 중심 (39.61, 2.92) · 반경 50km(정규화 상한). 메노르카는 밖이다. 카브레라는 항구·성이 있는 남쪽(51~52km)은 밖이고 북쪽 해안·코닐스 섬은 안이며, 사 드라고네라(51.4km)는 밖이다. 동서 끝(산텔름·캅데페라)의 여유는 1km 안팎이다 |

- 목소리는 **Gemini 3.8 Flash TTS · Sulafat**이다(Chirp 3 HD가 아니다). 카탈로그 머리의 `voice`는 세비야 것이라 장소마다 `voice`를 따로 적었다 —
  화면은 'AI 음성으로 읽었어요'만 쓰고 이 값은 읽지 않는다. 소리 크기는 세비야와 1.5dB 안이라 맞추지 않았다(말소리 RMS −16.7~−18.4 / −17.0dBFS).
- 만든 길: 웹 조사 세 갈래 → 원고 → 조사 메모를 주지 않은 검증 열 갈래(주장 30~52개씩, 지적 37건을 모두 고쳤다) → 덩어리(450자 이하)마다
  합성 → 받아쓰기로 원고와 대조(97% 이상만 들이고, 지시문을 읽거나 되풀이하면 다시) → 48kbps 모노 MP3. 제작 도구와 덩어리 캐시는
  저장소 밖(`stories-draft/mallorca-gemini/`, git 제외)에 있고 Gemini 키도 저장소에 없다.
- 원고는 `scripts/stories/source/mallorca/*.json`(+`narration/*.txt`)이고 트랙마다 이미 만든 음성의 경로(`audio`)를 적는다 — 아래 '제작 명령'.
  `factCheck`에는 검증이 **고친 곳만** 적었다(맞다고 본 나머지 주장은 `factCheckNote`에 개수로). 고친 문장이 원고에 남았으면 그 문장을 `CONFIRMED`로,
  틀린 내용을 뺐으면 원래 문장을 `OMITTED`로 적는다. 출처 제목은 세비야처럼 '누가 낸 어떤 자료 — 무슨 내용'이다(2026-10-31 독립 검토 뒤 주소에서 만든 이름을 바꿨다).
- 매칭은 세비야와 같은 규칙이다. 주의할 것: 이름이 '소예르'뿐인 장소도 소예르역 반경 안이면 기차 이야기가 붙는다(`nameMatches`는 짧은 쪽이
  긴 쪽에 들어 있어도 맞다고 본다 — 세 글자 이상).

## 원칙

- **이름만으로 붙이지 않는다.** '스페인 광장'은 마드리드에도 있고, '알카사르'는 세고비아·코르도바·톨레도에도 있다.
  매칭은 Google placeId가 같거나, **좌표가 반경 안이면서** 이름이 맞을 때만 한다(아래 규칙).
- **자동 재생·위치 추적은 하지 않는다.** 기존 음성 가이드와 같다. 사람이 누를 때만 재생한다.
- **AI 음성이라고 밝힌다.** 플레이어 아래에 'AI 음성으로 읽었어요 · 출처 N건'을 표시한다. 출처 목록은 펼쳐서 본다.
- **사실 확인을 거친 원고만 내보낸다.** 원고마다 출처 ID를 달고, 검수 표시(`reviewedAt`)가 없는 트랙은 카탈로그에 넣지 않는다.
- **여행 문서에 넣지 않는다.** 카탈로그는 앱이 들고 있는 별도 콘텐츠다. 동기화·공유 링크·내보내기·실행취소와 상관이 없다.

## 콘텐츠를 어디에 두는가 — 정적 파일(Vercel)

```
stories/catalog.json            ← 장소·트랙 목록 (작다, 매번 새로 받는다)
stories/seville/city.mp3
stories/seville/plaza-espana-core.mp3 · plaza-espana-more.mp3
stories/seville/alcazar-core.mp3 · alcazar-more.mp3
stories/seville/cathedral-01.mp3 … cathedral-14.mp3
```

- 웹과 같은 출처(`tripcanvas-ai.vercel.app/stories/…`)에서 정적 파일로 내보낸다.
  **API·DB를 건드리지 않으므로 NAS 배포 순서(API 먼저)가 필요 없고, NAS가 꺼져도 들을 수 있다.**
- 음성은 64kbps 모노 MP3로 만든다. 3분짜리가 약 1.4MB, 파일럿 전체는 약 25MB로 예상한다.
- 서비스 워커의 앱 셸 사전 캐시에는 넣지 않는다(설치할 때마다 25MB를 받게 된다).
  **듣거나 '오프라인 저장'을 누르면** 별도 캐시(`withj-stories-v1`)에 담는다. 비행기 모드에서도 재생된다.
- iOS는 같은 주소에서 카탈로그와 MP3를 받아 `Application Support/WithJStories/`에 **지문(`<sha256>.mp3`) 이름으로** 담는다(아래 '구현 메모 (iOS)').

### catalog.json 모양

```json
{
  "version": 1,
  "updated": "2026-10-2x",
  "voice": { "engine": "Google Cloud TTS Chirp 3 HD", "name": "Despina", "disclosure": "AI 음성으로 읽었어요" },
  "places": [
    {
      "id": "seville-alcazar",
      "kind": "PLACE",
      "name": "레알 알카사르", "localName": "Real Alcázar de Sevilla", "city": "세비야",
      "placeIds": ["ChIJ…"],
      "lat": 37.3831, "lng": -5.9903, "radiusM": 300,
      "aliases": ["알카사르", "세비야 알카사르", "Alcázar"],
      "tracks": [
        { "id": "core", "role": "CORE", "title": "알카사르, 핵심만", "src": "seville/alcazar-core.mp3",
          "seconds": 104, "bytes": 0, "sha256": "…", "sources": ["S12", "S13"], "reviewedAt": "2026-10-2x" },
        { "id": "more", "role": "MORE", "title": "더 듣기 — …", "src": "…" }
      ]
    },
    { "id": "seville-city", "kind": "CITY", "name": "세비야", "lat": 37.3891, "lng": -5.9845, "radiusM": 8000, "tracks": [ … ] }
  ],
  "sources": { "S12": { "title": "…", "url": "https://…" } }
}
```

대성당은 `role:"STOP"` 트랙 14개이고, 각 트랙에 `stop`(번호·현장에서 찾는 단서·스페인어 이름)을 둔다.

## 장소 매칭 규칙 (`matchStories` — 순수 함수, 유닛 테스트 대상)

장소 하나(`spot`)에 대해:

1. `spot.placeId`가 어떤 PLACE의 `placeIds`에 있으면 그 장소다.
2. 없으면 `spot.lat/lng`가 PLACE의 `radiusM` 안이고, 이름이 `name`·`localName`·`aliases` 중 하나와 맞으면(`placeNameMatch`) 그 장소다.
3. 좌표가 없는 장소는 붙이지 않는다. **이름만 같은 것은 매칭하지 않는다.**

CITY는 장소가 아니라 **날**에 붙는다. 그날 위치 있는 장소 중 하나라도 반경 안이면 그 날 머리에 '🎧 세비야 이야기'가 하나 뜬다.

테스트에는 반드시 마드리드 스페인 광장(40.4233, -3.7122)과 세고비아 알카사르(40.9527, -4.1325)를 넣어 **붙지 않는 것**을 확인한다.

## 화면

**웹 (PWA)**

- 장소 행의 '♫ 음성 가이드'와 장소 정보의 '음성 가이드' 버튼: 이야기가 있는 장소면 이름이 '🎧 With J 이야기'가 된다.
- 음성 가이드 창 맨 위에 With J 이야기 칸을 둔다. 핵심 트랙이 먼저 나오고 '더 듣기'는 그 아래에 있다.
  대성당은 관람 지점 목록(번호·단서·스페인어 이름)을 보여 주고, 지점을 눌러 듣는다. 다녀온 지점은 기기에 표시만 해 둔다.
- 오프라인 저장: '이 장소 이야기 저장(약 N MB)'을 누르면 받는다. 저장되면 '✓ 오프라인에서도 들을 수 있어요'로 바뀐다.
- **지금** 화면: 지금 있거나 다음에 갈 장소에 이야기가 있으면 카드에 🎧 버튼을 둔다.
- 재생은 기존 공유 플레이어를 그대로 쓴다. 창을 닫아도 계속 듣고, 재생 위치를 기억한다.

**iOS** (구현은 아래 '구현 메모 (iOS)')

- 일정 줄에는 '🎧 With J 이야기' 표시, 일자 제목 옆에 '세비야 이야기', 장소 편집기·장소 정보·`지금`의 다음 일정 아래에 'With J 이야기 듣기'.
- 카탈로그는 앱이 직접 받아 붙인다(서버를 거치지 않는 예외 — 정적 콘텐츠라 NAS가 꺼져도 들린다). 매칭 규칙은 `stories.js`의
  Swift 복사본이고 파리티 픽스처(`story-rules.json`)로 원본과 대조한다.
- 배경 재생·잠금 화면 조작은 앱 전체에 하나인 `StoryPlayer`가 한다.

## 콘텐츠 제작 과정 (저장소의 `scripts/stories/`)

```
원고(출처 ID 포함) → 사실 확인 → 듣기 좋게 다듬기 → 검수(reviewedAt) → TTS → 소리 크기 맞추기·MP3 → catalog.json(sha256·길이)
```

- TTS 키는 **저장소와 CI에 넣지 않는다.** 제작은 키가 있는 기기에서 사람이 돌린다. 이 클라우드 세션에는 Google Cloud 자격 증명이 없다.
  키를 환경 비밀값으로 넣어 주면 여기서도 만들 수 있다.
- 원고에서 메뉴 이름·출처 ID·파일 제목은 읽지 않는다. 발음 사전(`pronunciation-notes`)을 SSML로 적용한다.
- 무료 한도: 월 100만 자. 파일럿 전체는 약 3만 자로 예상한다.
- **이미 만든 음성**(트랙의 `audio` — 마요르카)은 합성하지 않고 그 파일의 길이·크기·지문만 재서 싣는다. 그 지역 폴더(`stories/<지역>/`) 안에
  저장소에 있어야 하고 장소에 목소리(`voice`)를 적는다(`--check`가 본다). **원고를 고치면 음성은 사람이 다시 만든다** — 카탈로그에는 원고가 실리지 않아
  고친 사실이 앱에 닿지 않으므로, 트랙의 `audioText`(음성을 만든 원고의 지문)가 지금 원고와 다르면 `--check`가 실패한다. 음성을 다시 만든 **뒤에** 지문을 바꾼다.
- **같은 이야기를 다른 자리에 붙일 때**는 `sameStoryAs: "<원본 id>"`만 적는다 — 원고·음성·출처·검수(`tracks`·`sources`·`factCheck`·`reviewedAt`·`voice`)를
  원본에서 물려받는다. 따로 들고 있으면 원본의 검수만 지워도 다른 쪽이 옛 음성을 그대로 내보낸다. 합성하는 트랙도 원본의 음성 경로를 써서
  한 번만 합성하고, 원본은 같은 지역 폴더 안에 있어야 한다(`--check`가 본다). 출처 ID는 카탈로그에서 하나로 모이므로
  장소끼리 같은 ID가 다른 출처를 가리키면 `--check`가 실패한다.

## 출시 단계

1. **웹 PR** — 카탈로그·매칭(lib)·음성 가이드 창의 With J 칸·오프라인 캐시·지금 화면 버튼, 그리고 세비야 콘텐츠.
   서버 변경이 없으니 웹 PR 하나로 나간다. 게이트: `npm run verify:all`.
2. **iOS PR** — 같은 칸과 파리티 픽스처, TestFlight.
3. 현장 확인 — 실제 iPhone에서 비행기 모드 재생·잠금 화면·장시간 재생을 확인한다.

## 지금 작업 트리에 있는 미배포 기능과의 관계

이 브랜치에는 아직 커밋되지 않았던 **'내 음성 파일 붙이기'(기기 전용)**와 **공유 파일 업로드(`trip_files`, 마이그레이션 0019)**가 있다.

- 제안: With J 이야기는 **main에서 새로 갈라 독립 PR**로 만든다. 공유 업로드는 DB 마이그레이션이 있어 API 먼저 배포해야 하고,
  게이트 미통과 항목도 남아 있다(`docs/trip-files-verification.md`). 묶으면 이야기 기능까지 그 일정에 묶인다.
- 기기 전용 '내 음성' 칸은 이야기 창과 한 화면을 쓰므로, 이야기 PR에 함께 넣거나 이야기 칸만 먼저 낼지 정해야 한다.
- 이 브랜치의 대용량 작업 파일(`docs/seville-tripcanvas-handoff/` 안의 zip·wav·jpg 약 15MB, `proto/` 이미지)은 저장소에 커밋하지 않는 것을 제안한다.
  원고(txt·json)만 `scripts/stories/source/`로 옮긴다.

## 구현 메모 (iOS)

- 코드: `ios/TripCanvas/Features/Stories/` — `StoryRules.swift`(`stories.js` 복사본: 정규화·매칭·표기) · `StoryLibrary.swift`(받기·지문 확인·담기)
  · `StoryPlayer.swift`(재생·잠금 화면) · `StoryViews.swift`(이야기 창·여는 버튼·탭 바 위 듣기 막대).
- ⚠️ **규칙은 `stories.js`를 먼저 고친다.** `next`의 `storyRulesParity.test.ts`가 원본으로 `ios/TripCanvasTests/Fixtures/story-rules.json`을
  다시 쓰고 `StoryRulesParityTests`가 복사본과 대조한다. 카탈로그는 지어낸 것이다 — 배포 카탈로그를 넣으면 음성을 낼 때마다 macOS CI가 돈다.
  갈라지기 쉬운 곳: 이름 길이·포함은 **UTF-16 코드 단위**(JS `length`·`includes`), 앞뒤 공백은 **JS `trim()` 집합**, 트랙 정렬은 **안정 정렬**,
  `sizeText`의 반올림은 `toFixed(1)`(딱 반은 올린다 — `String(format: "%.1f")`는 1.25MB를 1.2로 낸다), (0,0) 좌표는 위치 없음,
  주소 앞머리는 **문자가 아니라 스칼라**(`hasPrefix`는 결합 문자를 앞 글자와 묶는다), 어말 시그마는 양쪽 모두 **σ로 접는다**(JS `toLowerCase`는
  단어 끝의 Σ만 ς로 바꾸고 Swift `lowercased()`는 늘 σ다).
- **받는 길은 NAS가 아니라 웹 주소다**(`AppConfig.webBaseURL` + `stories/…`). `APIClient`는 NAS 토큰을 붙이므로 쓰지 않는다 —
  전용 ephemeral 세션(URLCache 끔·쿠키 끔)이고 토큰 없이 나간다. 로그인 없이 보는 샘플에서도 들린다.
- **담는 이름은 지문이다.** 웹 캐시는 URL을 열쇠로 써서 같은 경로에 새 음성이 올라오면 옛 것을 튼다 — 앱은 그 문제가 없다.
  받은 파일은 크기와 sha256이 카탈로그와 같을 때만 담고(`.completeFileProtectionUntilFirstUserAuthentication` — 잠긴 화면에서도 다음 이야기를 연다),
  폴더는 iCloud 백업에서 뺀다. 새 카탈로그를 받으면 거기 없는 음성은 지운다. 계정과 무관한 공개 콘텐츠라 로그아웃해도 지우지 않는다.
- **카탈로그는 오래 들고 있지 않는다**(`StoryLibrary.maxAge` 6시간). 음성을 다시 만들면 같은 경로에 새 지문이 올라오는데, 배경 재생 때문에
  며칠씩 살아 있는 앱이 옛 지문만 들고 있으면 그 트랙은 영영 받지 못한다. 여행 화면이 열리거나 앱이 돌아올 때 오래됐으면 다시 받고,
  디스크의 지난 사본으로 붙었으면 1분 간격으로 다시 받아 본다. 그래도 지문이 맞지 않으면 카탈로그를 한 번 바로 다시 받아 같은 트랙의
  새 지문으로 한 번 더 받는다(`file(for:placeID:)`). 못 받는 동안에는 지금 카탈로그를 그대로 쓴다.
- 재생기와 저장소는 **앱 전체에 하나**(`shared`)다 — `AppEnvironment`는 Siri 동작이 따로 만들기도 해서, 거기서 만들면 잠금 화면 조작이 두 번 붙는다.
  계정이 바뀌면 재생만 멈춘다. 이어폰을 뽑으면 멈춘다(성당 안에서 스피커로 이어 나오지 않게). 끊김은 `.spokenAudio`라 길 안내(지도 도보 안내)가
  말할 때마다 생긴다 — 시스템이 이어도 된다고 하고(`shouldResume`) 30초 안에 돌려받았을 때만 이어 튼다. 전화처럼 오래 끊긴 뒤에는 저절로 틀지 않는다.
  다 들으면 오디오 세션을 놓아(`notifyOthersOnDeactivation`) 끊겼던 음악이 이어지고, 듣기를 끝내면 잠금화면·이어폰 버튼도 받지 않는다.
- 화면이 꺼져도 들린다 — `UIBackgroundModes: audio`(`project.yml`과 `project-free.yml` **둘 다**). 장면이 `.inactive`·`.background`가 돼도 멈추지 않는다.
- 일정 줄 안에는 **누르는 버튼을 두지 않았다** — 줄 전체를 UIKit 탭 표면(`PlanSpotTapSurface`)이 덮어 눌리지 않는다. 표시만 하고, 여는 길은
  길게 누르기 메뉴 · VoiceOver 동작 · 줄을 눌러 열리는 편집기/장소 정보의 버튼이다.
- 듣기 막대(`StoryListeningBar`)는 탭 바 바로 위에 뜨고 내용은 그만큼 위에서 끝난다. **지도 탭에서는 세우지 않는다** — 지도가 아래 안전 영역을
  무시해 막대가 Google 로고를 덮는다(약관). 그때도 소리는 계속되고 잠금 화면에서 다룬다.
  막대와 `지금` 카드에서 여는 창은 `TripHomeView`가 띄운다 — 듣기를 끝내면 막대가, 다음 일정이 바뀌면 카드의 버튼이 계층에서 빠지는데,
  띄운 뷰가 빠지면 SwiftUI가 창도 내린다. 편집기·장소 정보처럼 그 자체가 창인 곳은 버튼이 직접 띄운다(창 위에는 그 창만 띄울 수 있다).
- CryptoKit은 SHA-256 해시에만 쓴다 — 수출 규정상 면제(`ITSAppUsesNonExemptEncryption: false`는 그대로).
- 확인되지 않은 것: 실기기에서의 잠금 화면 재생·이어폰 뽑힘·전화 끼어듦·장시간 재생. CI는 시뮬레이터 빌드와 XCTest만 본다.

## 제작 명령

```bash
node scripts/stories/build-stories.js --check   # 원고 검사(키 필요 없음 — 유닛 테스트도 같은 검사를 돈다)
GOOGLE_TTS_API_KEY=… node scripts/stories/build-stories.js --draft   # 검수 전 원고까지 stories-draft/에(올리지 않는다)
GOOGLE_TTS_API_KEY=… node scripts/stories/build-stories.js           # 검수한 원고만 stories/에 + catalog.json
```

원고는 `scripts/stories/source/<지역>/*.json`(`seville`·`mallorca` — `REGIONS`)이다. 키는 **합성할 트랙이 있을 때만** 묻는다 —
바뀐 원고가 없으면(지문이 같고 파일이 있으면) 키 없이 카탈로그를 다시 쓴다(2026-10-31 마요르카를 실을 때 세비야는 한 글자도 다시 합성하지 않았다).
'파일'은 쓰는 폴더의 파일이라, `--draft`는 `stories-draft/`가 비어 있으면(새 체크아웃) 세비야도 합성하므로 키가 필요하다.
들어 보고 사실 확인 기록(`factCheck`)이 전부 `CONFIRMED`이거나, 확인하지 못한 사실마다
처리(`resolution` — 본문에서 뺐으면 `OMITTED`, 단정하지 않게 고쳤으면 `HEDGED`)가 적혀 있으면 그 장소에 `reviewedAt`을 적는다 — 검수 표시가 없는 트랙은 카탈로그에 들어가지 않는다. 같은 원고는 다시 합성하지 않는다(`build-state.json`).

**쉼(띄어읽기)은 엔진에 맡기지 않는다**(2026-10-28 — "띄어읽기가 거의 안 되는 수준"). 트랙을 통째로 보내던 때 Chirp 3 HD는 문단 사이의
`[pause long]`을 빼먹기도 하고(스페인 광장 72초에 0.7초 넘는 쉼이 한 번도 없었다) 7초로 늘리기도 했으며(대성당 1번), 쉼표는 그냥 지나갔다
('카스티야, 레온, 아라곤, 나바라'가 8초 동안 쉼 없이). 지금은 이렇다:

- **문장마다 따로 합성한다**(`sentencePlan` — 빈 줄이 문단, `. ? !` 뒤 공백이 문장 경계). 쉼표 뒤에만 `[pause short]`를 넣는다 — 한 문장 안에서는 0.2~0.4초로 지켜졌다.
- 받은 소리(LINEAR16)의 앞뒤 쉼을 걷고(`trimSilence`, -45dB · 첫소리 앞 40ms·끝소리 뒤 150ms는 남긴다) 문장 사이 **0.6초**, 문단 사이 **1.2초**를
  직접 만든다(`joinTrack` · `PAUSE`). 이 길이는 **들리는 쉼**이다 — 남긴 끝소리 꼬리 중 -35dB 아래인 부분(`edgeQuiet`)만큼 무음을 덜 넣는다. 고정 무음만
  끼웠을 때는 꼬리가 문장마다 달라 문장 사이가 0.7~1.1초, 문단 사이가 2초 넘게 흔들렸다. MP3(48kbps)는 ffmpeg가 굳힌다 — **합성하는 기기에 ffmpeg가 필요하다**.
  소리 처리를 바꾸면 `MAKE_VERSION`을 올린다(지문에 들어가 모든 트랙을 다시 만든다).
- 문장마다 들이기 전에 잰다(`sentenceProblem`): 문장 안 쉼이 1초를 넘거나(-35dB로 잰다 — 엔진이 '쉰' 자리에도 숨소리 바닥이 -45~-35dB로 깔려 있어
  낮게 보면 7초 쉼도 안 잡힌다) **말 빠르기**가 4.2~8.5자/초 밖이면(12자 미만 문장은 재지 않는다) 두 번까지 다시 합성한다.
  2026-10-27 대성당 13번이 원고는 65초 분량인데 89초로 나왔고 검사로는 드러나지 않았던 일이 이 검사를 만들었다.
- 그래도 어긋나면 그 트랙을 빼고 카탈로그를 쓰지 않은 채 실패한다 — 다시 돌리면 그 트랙만 합성한다. 합성한 트랙마다 길이·문장 수·쉼을 한 줄로 찍는다.

이 검사들은 **내용을 듣지 않는다**: 잘못 읽은 낱말, 어색한 억양은 사람이 들어야 안다. 2026-10-22 첫 음성은 디코딩·음량·무음·말 빠르기를 모두 통과했지만
띄어읽기가 무너져 있었다 — 새로 만든 음성은 **올리기 전에 한 편이라도 끝까지 들어 본다.**

같은 주소에 다시 만든 음성이 올라와도 웹은 담아 둔 사본의 지문을 카탈로그와 맞춰 보고(`storyFresh` — 담을 때 `X-Story-Sha256` 머리글을 적는다), 다르면 새로 받는다.
못 받으면(비행기 모드) 옛 사본이라도 튼다. 앱은 원래 지문 이름(`<sha256>.mp3`)으로 담아 저절로 바뀐다.
