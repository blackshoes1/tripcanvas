# 기기에서 확인할 것 (2026-09-22 · tc-v225 기준)

여기 적힌 것은 **CI가 통과시켰지만 아직 실제 기기에서 본 사람이 없는 변경**이다. 게이트가
못 보는 종류를 모아 뒀다 — 컴파일과 단위 테스트는 "값이 맞는가"를 보지 "손가락에 닿는가·
눈에 어떻게 보이는가"를 보지 않는다.

- **iOS는 시뮬레이터 빌드 + XCTest까지만 돌았다.** 작업 컨테이너에 Xcode도 기기도 없어서,
  `Build + unit tests (simulator)`가 초록이라는 말은 **타입이 맞고 테스트가 통과했다**는 뜻이지
  화면이 제대로 보인다는 뜻이 아니다.
- **웹은 데스크톱 Playwright까지만 돌았다.** 390px 뷰포트 시나리오가 있지만 실제 터치·
  실제 사파리·실제 서비스 워커 캐시는 다르다.
- 색·간격·터치 크기·실시간처럼 **사람 눈과 두 기기가 필요한 것**은 여기서만 확인된다.

⚠️ 확인하다 어긋난 것이 나오면 그 자리에 무엇을 봤는지 적고 고치는 쪽으로 넘긴다.
"대충 맞는 것 같다"로 지우지 않는다 — 이 목록의 쓸모는 **아직 안 본 것이 무엇인지 아는 것**이다.

|---|---|---|

## 1. 웹 — 폰 브라우저 (여기부터는 기기만 있으면 된다)

### 1-1. 명소 예약요건 편집기 (#275)

장소를 열고 **상세 설정** 펼치기 → *명소 예약·입장 준비*.

- 요건 셀렉트박스 네 가지가 보이고 고르면 저장된다 (예약 필수 / 예약 권장 / 예약 없이 입장 가능 / 예약 요건 확인 필요)
- `공식 정보를 지금 확인했어요` 버튼을 누르면 그 아래 확인 시각이 찍힌다
- 공식 링크에 `http://`를 넣으면 **저장이 거절되고 이유 문장이 뜬다**(https만)
- **누르기 좋은가** — 좁은 화면에서 셀렉트·체크박스·버튼이 서로 붙어 있지 않은지. 데스크톱에서만 봤다

### 1-2. 일자 카드의 예약요건 칩 (#275)

- '예약 필수'인데 아직 예약 안 한 장소에만 **주의색** 칩(`.admNeed`)이 붙는다
- '확인 필요'뿐인 장소에는 **아무것도 안 붙는다** — 모든 명소에 칩이 붙으면 정작 필수인 곳이 묻힌다
- 공식 링크가 있으면 `공식 예약` 칩이 따로 붙고, 탭하면 새 탭으로 열리되 **일자 카드가 열리지 않는다**(`stopPropagation`)

### 1-3. 영수증 사진 개수 안내 (#275)

폰(iOS 앱)에서 비용 항목에 사진을 붙인 뒤 **웹에서 같은 항목을 연다.**

- 목록 줄에 `📎 사진 N장`, 편집기에 `영수증·품목 사진 N장 — 붙인 기기에서만 볼 수 있어요`
- 웹에서 그 항목을 **저장해도 사진 수가 줄지 않는다**(저장에서 떨어뜨리지 않는지가 핵심이다)

### 1-4. 여행 목록 진입점 하나 (#278)

- 헤더의 **여행 피커**가 데스크톱·모바일 양쪽에서 보이고 현재 여행 이름을 말한다
- ☰ 메뉴에 **'여행 목록'이 없다**(피커로 합쳤다)
- 피커를 탭하면 전환·삭제가 되는 그 모달이 열린다

### 1-5. ☰ 안의 것을 바깥에서 알리기 (#278)

- 준비 메모나 가고 싶은 곳이 있으면 ☰ 버튼에 **점**, 메뉴 항목에 **개수**
- 챙긴 메모(`done`)는 세지 않는다
- 후보 개수는 **이번 세션에서 그 보드를 받아 본 적이 있을 때만** 뜬다 — 안 떠도 버그가 아니다
- 둘 다 없으면 점도 개수도 없다

### 1-6. 읽기 전용 링크 복사 안내 (#278)

- 복사하면 토스트가 `지금 이 순간의 사본으로 링크를 복사했어요 — 이후 수정은 반영되지 않아요`
- 토스트의 `같이 고치려면`을 탭하면 멤버·초대로 넘어간다 — **토스트가 사라지기 전에 손가락이 닿는지**가 기기에서만 보인다

### 1-7. 지도 범례로 날 바꾸기 (#278)

**재생 중에** 지도 범례의 날짜를 탭한다.

- 재생이 멈추고 **새 범위로 다시 시작한다**(필터바 칩과 같은 동작)
- 전에는 범례가 `activeDay`를 직접 바꿔 재생 처리가 빠져 있었다

### 1-8. 예약 목록의 기준 문장 (#278)

- 예약 목록 맨 위에 `여기 금액은 예약 전액이에요 — 일자 카드의 '하루 비용'은 이걸 날수로 나눈 하루치입니다`
- 실제로 일자 카드의 하루 비용과 숫자가 **다르게 보이는 여행**에서 이 문장이 그 차이를 설명하는지

### 1-9. 작은 버튼 네 곳 (#279)

`.btn.sm` 한 이름으로 모았다 — 인라인 `style`로 각자 만들던 것을 걷어냈다.

- 장소 모달의 `지도 클릭으로 위치 지정`
- 호텔 가격 후보의 `이 호텔이에요`
- 버전 이력의 `복원`
- 초대의 `취소`

**손가락이 닿는가**가 전부다(`min-height:26px`). 네 곳이 같은 크기로 보이는지도 같이 본다.

### 1-10. 라이트·다크 양쪽 (#279)

상태 배지 색을 토큰으로 옮겼다. E2E가 계산된 색을 양쪽 테마에서 읽어 값이 그대로인지 보지만,
**두 테마를 실제로 전환해 보는 것**은 여기서만 된다.

- 필터바의 `☷ 보기 설정` → `◐ 테마 전환`으로 라이트 ↔ 다크를 오가며 가고 싶은 곳 보드의 배지 세 가지를 본다
- **덤으로 그 드롭다운 자체를 본다** — 모바일 필터바는 `overflow-x:auto` 스크롤 컨테이너라 패널이
  44px에 갇혀 거의 안 보이던 자리다(`position:fixed`로 빼냈다). 폰에서 패널이 통째로 보이는지
- **강조 버튼 글자는 양쪽에서 흰색이다** — 여기가 검게 보이면 토큰화가 잘못된 것이다(다크에서
  초록 배경에 검은 글자). E2E가 지키고 있지만 눈으로 한 번 본다

## 2. iOS — 실기기 (새 빌드가 필요하다)

### 2-1. 실시간 — 두 기기 또는 앱 + 웹 (#268)

**M7의 진짜 확인은 이것뿐이다.** 시뮬레이터 테스트는 소켓을 열지 않는다.

- 일행(또는 웹)이 일정을 고치면 **`지금`·`일정` 탭이 그대로 따라온다**(전에는 보드를 닫으면 소켓이 끊겨 안 따라왔다)
- '가고 싶은 곳' 보드를 열었다 **닫아도 일정의 실시간이 살아 있다**(`disconnect(key:)`가 남은 구독자가 있으면 소켓을 안 닫는다)
- 앱을 백그라운드로 보냈다 돌아오면 두 화면이 각자 다시 붙는다
- **못 붙어도 앱이 멀쩡한지** — 당겨서 새로고침이 폴백이다
- 내 편집의 에코로 일정을 다시 읽지 않는지(화면이 깜빡이지 않는다)

### 2-2. 자연어 요청 (#273)

`지금` 화면의 문장 입력(`IntentField`).

- "오늘 좀 피곤해서 많이 걷기 싫어"를 넣으면 **에코가 뜬다**(무엇으로 알아들었는지)
- 못 알아들으면 **알아들은 척하지 않는다**
- **키보드가 입력칸을 가리지 않는지**, 제출 후 키보드가 내려가는지 — 기기에서만 보인다
- 지우면(`onClear`) 원래 제안으로 돌아온다
- 앱을 껐다 켜면 **그 문장이 되살아나지 않는다**(저장하지 않는 것이 규칙이다)

### 2-3. 참여자 편집 '누가 가나요' (#272)

장소 편집기(`SpotEditorView`).

- 일행이 둘 이상이고 편집 권한이 있을 때만 뜬다 — 혼자 쓰는 여행에서는 **안 뜨는 것이 정상**
- **분리가 없는 여행에서도 뜬다** — 전에는 `hasSplits`일 때만 멤버를 받아 첫 분리를 만들 수 없었다
- 전원을 고르면 **비워진다**('모두'와 같은 뜻)
- **칩이 줄바꿈될 때 레이아웃이 무너지지 않는지** — 이름이 긴 멤버가 넷 이상일 때. 기기에서만 보인다

### 2-4. 탭·시트가 같은 모델을 쓰는가 (#278)

네 진입점이 여행 화면의 공유 모델을 받게 했다 — 전에는 각자 만들어 **같은 목록을 최대 3벌** 받았다.

| 어디서 | 무엇을 연다 |
|---|---|
| `지금`의 예약 카드 | 예약 정보 보기 |
| `지금` 하단 | 예약 정보 |
| `일정`의 링크 | 가고 싶은 곳에서 가져오기 |
| `지도`의 시트 | 날짜에 배치하고 함께 고르기 |

- **통과 기준: 열 때 로딩 스피너가 돌지 않는다**(이미 받아 둔 것을 쓰므로). 60초 안에 다시 열면 요청이 0이다
- 네 곳 모두 `NavigationLink`라 SwiftUI 환경이 내려가는 것이 맞지만, **`.environment`가 실제로 닿았는지는 화면이 말해 준다**
- ⚠️ 안 닿았으면 조용히 자기 모델로 떨어진다 — **기능은 그대로고 네트워크만 예전과 같다**. 즉 "안 되는 것"이 아니라 "좋아지지 않은 것"이라 눈치채기 어렵다

### 2-5. 색 46건 (#279)

`.orange`·`.red`·`.green`·`.blue` 직접 호출을 `Ink.*`로 옮겼다(23개 파일). **값이 아니라 보이는 것이 바뀐 자리가 있다.**

- **가고 싶은 곳 보드의 배지**를 제일 먼저 본다 — `mixed`('조금 갈려요')가 **노랑 → 빨강**으로 바뀌었다.
  웹과 같은 색을 말하게 한 것이지만 **앱에서 더 세게 읽힐 수 있다**
- 나머지 22개 파일은 값이 같아야 한다 — 경고·오류·완료·상대가 정한 것의 색이 **전과 같은지** 훑는다
- 구글 지도 마커만 시스템 색을 그대로 쓴다(SDK가 `UIColor`를 요구하고 타일 위에서 읽혀야 한다) — 타일 위에서 여전히 보이는지

### 2-6. 예약 열기 · 항공편 한 줄 (#271)

- `지금`의 다음 일정 카드에 `예약 열기`가 뜨고 **실제로 열린다**
- 일자 목록 맨 앞의 항공편 한 줄(`IB3100 · MAD 08:05 → SVQ 09:00`)이 제 자리에 있고 **드래그 순서를 건드리지 않는다**

## 3. 확인이 아니라 결정이 필요한 것 (사람이 정한다)

기기에서 보면 판단이 설 것들이다. 고치려면 웹·iOS를 **같이** 바꿔야 한다.

- **`split`과 `mixed`의 색 세기가 뒤바뀌어 보인다** — `split`(CONFLICT, '의견이 갈려 있어요')이
  약한 색이고 `mixed`(MIXED, '조금 갈려요')가 센 색이다. 웹을 그대로 옮긴 것이라 앱만 고치면 갈린다
- **`border-radius`가 15가지 값**이다 — 묶을지, 묶는다면 몇 단계로 할지
- **iOS의 이모지 ↔ SF Symbols** — `roleIcon`·`Reaction.icon`은 웹 문장에도 같은 **글자**로 쓰여서
  벡터로 바꾸면 두 매체가 갈린다. 화면만 바꿀지 문장까지 갈지

## 부록 — 이 컨테이너에서 매번 SKIP되는 것

게이트를 돌릴 때마다 같은 셋이 FAIL/SKIP으로 나온다. **코드 문제가 아니다**:

- `rls.integration` · 복구 리허설 — `pg_ctl: cannot be run as root`(로컬 PostgreSQL을 못 띄운다)
- E2E `가져오기·내보내기와 390px 모바일 핵심 화면` — 컨테이너 Chromium이 `download` 속성을 떨어뜨린다

셋 다 **CI에서는 초록**이다. 그래도 `SKIP은 통과가 아니다` — 이 셋이 덮는 것은 CI 로그로 확인한다.
