# Next 웹 2차 전환 — 협업·실시간 실행 프롬프트

Trip Canvas(제품명 With J)의 최종 웹은 Next로 결정됐다. 1차 전환으로 자체 인증, 공통 API 여행 저장·삭제·충돌, 버전 이력, 가격 관측 읽기와 예약 화면 동기화를 연결했다. 이제 기존 정적 웹과 API의 실제 구현을 근거로 Next의 협업·실시간 흐름을 완성해줘.

## 시작과 범위

- 최신 AGENTS.md와 하위 지침을 읽고 원격을 fetch한다. `chore/system-architecture`의 PR 상태와 커밋을 확인한다. 미병합이면 1차 변경을 포함하는 별도 작업 공간·브랜치에서 이어가고, 원래 작업 공간의 iOS 변경을 섞지 않는다.
- 기준 자료: `docs/system-architecture-review.md`, `docs/architecture.md`, `docs/collaboration.md`, `docs/nas-release.md`. 문서보다 현재 코드와 계약을 우선하고 운영 활성화 여부를 구분한다.
- 1차 전환 커밋은 `64f6087`, `950b47a`이며 후속 문서 커밋이 있을 수 있다. 이미 완료한 인증·동기화를 다시 만들지 않는다.
- 작은 구현 단위로 진행하고 각 단위의 성공 기준과 검증 결과를 남긴다. 다음 범위의 실제 구현·테스트까지 완료하며 계획만 쓰고 끝내지 않는다.
- 운영 배포·PR merge·운영 데이터 수정·실제 사용자 초대나 알림 발송은 실행하지 않는다. 합성 계정과 격리 환경으로 검증한다. 승인 전 준비·검증·PR 작성은 진행한다.

## 1. 계약과 기능 차이 확인

정적 웹의 협업 UI·공통 `collab.js`·`api.js`, Next 서버의 협업 라우트·서비스·저장소, `/me`, 실시간 중계와 iOS의 재조회 흐름을 읽어 실제 엔드포인트·역할·이벤트 모양을 확인한다. 파일 이름만으로 동등성을 판단하지 않는다.

초대 미리보기/수락, 멤버 목록, 역할 변경, 내보내기, 나가기, 후보·의견·활동 기록 중 기존 웹에서 실제 제공하는 흐름을 표로 만들고 Next에 없는 부분을 구현한다. 새 협업 제품 기능은 추가하지 않는다.

## 2. Next 협업 UI 연결

- 공통 API transport와 현재 자체 인증을 재사용한다. Supabase 직접 접근이나 새 인증 세션 저장소를 만들지 않는다.
- 초대 링크 진입 → 제한된 미리보기 → 필요시 로그인 → 사용자 수락 → 여행 조회의 흐름을 연결한다. 로그인 전후에 초대 의도를 보존하되 원문 토큰이 로그·분석·불필요한 저장소에 남지 않게 한다. 자동 수락하지 않는다.
- OWNER/EDITOR/VIEWER별 읽기·편집·관리·나가기·삭제 권한을 현재 API 계약대로 반영한다. UI를 숨기는 것과 서버 인가를 별도로 검증한다.
- 만료·취소·잘못된 초대, 내보내진 멤버, 권한 변경, 401/403/404를 빈 상태나 성공으로 숨기지 않는다. 권한 거절은 재시도 루프에 넣지 않는다.
- 후보·의견 등 공유 작업은 기존 정적 웹과 같은 확인·반영 정책을 따른다. 사용자에게 보이는 용어는 AGENTS의 브랜드 규칙을 따른다.

## 3. 실시간 재조회 연결

- `/me`의 실제 실시간 설정과 기존 중계 프로토콜을 사용한다. 이벤트는 변경 신호로 받고 권한이 적용된 API에서 최신 데이터를 읽는다.
- 이벤트·탭 복귀·재연결이 중복되어도 연결이나 조회가 무한히 늘지 않게 한다. 로그아웃·계정 전환·여행 전환·컴포넌트 해제 때 연결과 구독을 정리한다.
- 로컬 미저장 편집은 원격 이벤트로 덮어쓰지 않는다. 기존 revision CAS·충돌 UI·tombstone 처리를 재사용한다. 새로운 충돌 엔진이나 CRDT를 도입하지 않는다.
- 실시간 연결이 끊겨도 저장 API와 재조회 폴백이 동작해야 한다. 이벤트 유실 후 재연결로 최신 상태를 회복하고, 권한이 제거된 여행을 계속 구독하지 않는다.
- Next 일정과 예약 화면을 오갈 때 구독 중복·저장 누락·불필요한 로그인 병합이 없는지 확인한다.

## 4. 검증과 완료 기준

의미 있는 서비스·브라우저 회귀 테스트를 추가하고 합성 사용자 OWNER/EDITOR/VIEWER로 다음을 검증한다.

1. 초대 생성·미리보기·로그인·수락·여행 표시와 만료/취소 처리.
2. VIEWER의 API 쓰기 거절, EDITOR의 소유자 전용 작업 거절, 역할 변경·내보내기·나가기 반영.
3. 두 브라우저의 변경 전파, 동시 편집 충돌, 삭제 전파, 로컬 편집 보존.
4. 연결 끊김·재연결·탭 복귀·중복 이벤트·계정 전환 후 정확한 재조회와 연결 정리.
5. 일정/예약 화면 이동, 새로고침 후 인증·권한 유지와 기존 1차 전환 테스트 회귀 없음.

브라우저 대역 테스트와 실제 로컬 API·PostgreSQL·실시간 중계 통합 검증을 구분해서 보고한다. 실행할 수 없는 검증은 이유와 대체 검증을 명시하고 PASS로 처리하지 않는다. 실사용자와 운영 데이터는 사용하지 않는다.

`npm run verify:all`을 실행한다. 루트 웹 자산을 수정했다면 버전 규칙을 따른다. 문서만 추가한 경우 불필요하게 전체 게이트를 반복하지 않는다. Docker 실행 환경이 있으면 이미지 빌드와 격리 Compose 연결도 검증하고, 없으면 미검증으로 남긴다.

## 5. 마무리

- 현재 구조와 잔여 기능 비교표를 갱신하고 완료/미검증/후속 범위를 구분한다.
- PR에는 변경 이유, 사용자 영향, 실행한 검증, 미실행 항목, 배포 대상, 되돌리는 방법을 적는다. CI 실패가 있으면 원인을 확인하고 코드 문제는 수정한다. 외부 러너 문제를 코드 통과로 바꾸지 않는다.
- 운영 웹은 기존 정적 PWA를 유지한다. PWA·회원가입/복구 UX·실키 지도 검증은 별도 후속 단계로 기록한다. 협업 검증에 꼭 필요한 최소 인증 연결만 이번 범위에 포함한다.
- 완료 기준은 Next에서 기존 협업 흐름과 실시간 변경 반영이 동작하고, 권한·충돌·오프라인 복귀 회귀 검증이 통과하며, 검토 가능한 PR과 결과 문서가 남는 것이다. 운영 전환 완료로 보고하지 않는다.
