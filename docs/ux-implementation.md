# UI/UX 개선 구현 결과

기준: 2026-09-13 main `5c16deb`. 브랜치: `feat/ux-review-improvements`. 웹 버전: `tc-v196`.

개발 요구사항은 [개발 프롬프트](ux-development-prompt.md)에 저장했다.

## 구현

- iOS 장소·예약 편집이 실제 저장 결과를 기다린다. 실패하면 편집기를 유지하고 오류와 입력 복사·공유를 제공한다. 수정 중 시트 쓸어 닫기를 막고 취소 시 폐기를 확인한다. 장소를 다른 날로 옮길 때도 편집한 내용을 한 요청으로 함께 저장한다.
- 편집 모델은 실제 성공 여부를 반환한다. 동시 저장과 미해결 충돌의 무조건 재시도를 막는다. 충돌 후 화면이 이미 이전 일정으로 돌아갔다는 사실을 안내한다. 자동 병합·덮어쓰기는 하지 않는다.
- iOS 검색 결과는 장소 편집기에서 확인한 뒤 저장한다. 첫 목록 조회 실패는 빈 여행 안내 대신 재시도 화면으로 표시한다.
- iOS 예약·같이 짜기·가고 싶은 곳은 여행 공통 영역에서 연다. 예약 딥링크는 예약 패널로, 제안·다시 맞추기는 지금 탭으로 연결한다. 최초 로딩 전에 도착한 목적지도 보관한다. 기록/공유함 링크는 미지원 안내를 표시한다.
- iOS 상태 배지 기본 글자색을 더 진하게 바꾸고, 남은 일정에 완료·건너뛰기 메뉴를 표시한다.
- 웹 온보딩의 With J 이름, 새 여행 최초 포커스, 포커스 순환, 배경 inert, 닫은 뒤 복귀를 적용했다. 지연된 모달 자동 포커스가 사용자가 이미 입력 중인 칸에서 포커스를 빼앗지 않게 했다.
- 웹 빈 여행에서는 이전 여행 지도를 덮고 첫 장소 검색으로 안내한다. 확인된 첫 장소를 저장하면 지도를 그 위치로 맞춘다. 읽기 전용에서는 검색 버튼을 숨긴다.
- 예약·입장 시각을 웹 장소 기본 폼에 올리고, 내가 정한 도착 시각 및 자동 예상의 차이를 설명한다.
- 웹 저장 상태를 지속적으로 표시한다. 기기 저장 실패, 서버 저장 대기/진행/완료, 오류, 권한 거절, 충돌을 구분하며 가능한 경우 재시도/변경 확인을 제공한다.
- 웹 메뉴를 여행·같이 짜기·파일/설정으로 묶고 읽기 전용 링크와 멤버 초대를 구분한다.

## 구현 범위의 한계

- 목적지 이름을 도시 ID·좌표·시간대로 정규화해 공통 계약에 저장하는 확장은 아직 하지 않았다. 빈 지도의 잘못된 이전 위치 표시를 해결하고 사용자가 확인한 첫 장소와 연결하는 단계다.
- iOS 충돌은 초안을 유지하고 복사할 수 있지만 필드별 자동 병합이나 충돌 비교 화면은 없다. 앱 프로세스가 종료되는 경우까지 초안을 디스크에 보관하지는 않는다.
- 제안 딥링크는 지금 화면으로 연결하며 특정 제안 카드 자동 스크롤은 아직 없다. 예약 링크 계약에는 예약 ID가 없어 예약 목록을 연다.
- 준비 요약, 일정 변경 전후 비교, 위치 없는 장소 일괄 확인, 지난 여행 보관·검색, 외부 지도 앱 선택은 프롬프트의 후속 확장 범위로 남겼다.

## 검증

`npm run verify:all`을 전체 실행했다. 아래 재검증을 포함해도 **전체 게이트 통과로 판단하지 않는다**. 실제 PostgreSQL과 iOS 검증이 남았고 POSIX 전용 테스트가 Windows에서 실패한다.

| 검사 | 결과 |
|---|---|
| 구문·버전 동기·lint·루트 tsc·시크릿 스캔 | 통과 |
| 루트 유닛 | 388 통과, 7 실패, 3 SKIP. 실패는 `/bin/bash` 직접 실행 검사 5개와 `/bin/sh` 백업 검사 2개로 Windows에서 프로세스를 시작하지 못함. SKIP은 PostgreSQL/외부 키 필요 검사 |
| 루트 통합 | 128개 통과. 첫 장소 프레이밍에 필요한 카카오 지도 모형을 보완한 뒤 전체 재검증 |
| 웹 Playwright | 전체 49개 통과. 이후 마지막 안내 문구/충돌 버튼 수정에 대한 추가 4개 통과 |
| Next lint·tsc·build·tools:build | 통과 |
| Next Vitest | 최초 842 통과, 인증 초기화 hook 시간 초과 2개. 해당 파일을 `--maxWorkers=1 --hookTimeout=30000`으로 재검증하여 15개 모두 통과 |
| Next API 연결 E2E | 검토용 정적 서버가 8000 포트에 남아 최초 실행 실패. 서버를 정리하고 올바른 Next 서버로 재실행하여 4개 통과 |
| 실제 PostgreSQL RLS | SKIP — 로컬 PostgreSQL 바이너리 없음 |
| iOS XCTest·Release·XcodeGen | SKIP — Windows에 macOS/Xcode 없음. 작성한 테스트와 통과한 테스트를 구분해야 함 |

웹은 agent-browser로 모바일 390×844 및 데스크톱 1440×1000에서 온보딩, 새 여행, 장소 폼을 직접 확인했다. 실계정 서버 쓰기를 실행하지 않았으며 자동 테스트는 가짜 API로 검증한다.

iOS에 저장 결과·실패 후 재시도·충돌 보호·중복 저장 방지·이동 시 초안 보존·목록 조회 실패 재시도 테스트를 추가했다. 이 테스트들은 이 머신에서 실행하지 못했다. iOS 시트 동작, 큰 글자, VoiceOver, 실행 중/콜드 스타트 딥링크는 Mac·기기에서 확인해야 한다.

## 릴리스와 되돌리기

초안 PR로 검토하며 main에 merge하지 않는다. CI 및 iOS 검증을 확인한 뒤 배포 여부를 판단한다. API·DB 스키마·NAS 배포 설정 변경은 없다. 되돌릴 때는 개선 커밋을 revert하고 웹 캐시 버전을 새로 올린 뒤 게이트를 실행한다.
