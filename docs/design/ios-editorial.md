# iOS 매거진 디자인과 공유 여행 표지

승인된 시안의 종이색·잉크·올리브 색을 공통 팔레트에 적용한다. 나의 여행은 사진을 중심으로, 하루 일정은 사진 없이 시간·장소·이동 순서가 읽히는 목록으로 구성한다.

- 여행 목록: 대표 사진, 명조 제목, 날짜·도시, 여행 열기·삭제/나가기 유지.
- 하루 일정: 밑줄 날짜 탭, 명조 제목, 올리브 타임라인, 얇은 이동 구분선, 장소 추가. 기존 스와이프 판정·탭 취소·재정렬·보기 권한·장소 우선순위를 유지한다.
- 나눔명조 Regular를 OFL 라이선스와 함께 번들한다. 제목은 Dynamic Type에 따라 커지고 본문·시간·버튼은 시스템 글꼴을 유지한다. 다크 모드도 지원한다.

## 표지 사진

기본 사진은 첫 번째 유효한 도시의 Wikipedia 항목에서 찾는다. 좌표가 없거나 동음이의어인 항목은 쓰지 않는다. Wikimedia Commons의 저작자·공개 라이선스가 확인된 JPEG/PNG/WebP만 사용하고 출처 링크를 표시한다. 미조회·실패 시 도시명 표지를 남긴다. 여행 이름·일정·로그인 토큰은 외부 사진 서비스에 보내지 않는다.

여행 목록의 **표지 바꾸기**에서 내 사진을 고르고 미리보기 후 저장한다. 원본은 보내지 않는다. 앱이 1200px 이하, 250KB 이하 JPEG로 축소하고 서버도 유효한 JPEG인지 검사·재인코딩하여 EXIF/GPS를 제거한다. 대표 사진으로 되돌리기는 사용자 사진을 null로 저장한다.

표지는 인증된 `GET/PUT /api/v1/trips/:tripId/cover`로 조회·저장한다. 여행 본문이나 공유 링크에는 이미지를 넣지 않는다. 별도 `trip_covers` 표에 여행당 한 장을 저장하며, 여행과 동일한 권한으로 다른 기기·일행·웹이 조회한다. OWNER/EDITOR만 수정하고 VIEWER는 조회만 한다. 비회원·나간 멤버·삭제된 여행은 접근할 수 없다. 응답은 no-store이며 앱이 공개 사진 URL을 만들지 않는다.

표지 revision은 일정 revision과 별개다. 동시 저장은 CAS로 하나만 성공하고 오래된 저장은 409로 거절한다. 삭제 후에도 revision을 남겨 오래된 최초 저장이 되살아나지 않는다. 앱은 충돌을 자동 덮어쓰지 않으며 닫고 다시 열어 최신 표지를 확인하게 안내한다. 앱 복귀·목록 새로고침, Next 웹 포커스 복귀, 정적 웹의 여행 목록 재열기에서 새 표지를 읽는다. 표지 자체의 실시간 푸시는 추가하지 않았다.

## 배포와 복귀

마이그레이션 `0014_trip_covers.sql`은 새 표와 외래키·크기 제약만 추가하며 기존 여행 데이터를 바꾸지 않는다. 기존 앱과 호환된다. NAS의 migrate/API/realtime을 같은 커밋으로 선배포한 후 웹 merge와 iOS 배포를 진행한다. 운영 마이그레이션은 프로젝트 승인 규칙을 따른다.

웹 캐시 버전은 tc-v209. 기존 NAS 배포 스크립트의 Bash 3.2 빈 배열 오류도 수정하여 인자 없는 자체 업데이트가 동작하도록 한다. 사진 변경 실패는 기존 사진과 일정 편집을 훼손하지 않는다. 구버전 서버에서는 업로드를 열지 않고 재조회 버튼을 표시한다.

되돌릴 때는 이전 앱·API·웹으로 복귀하며 추가된 표는 보존한다. 표를 삭제하면 사용자 표지가 손실되므로 rollback 과정에서 drop하지 않는다. 기존 DB 백업/복구 대상에 새 표가 포함된다. 사진은 여행 문서 스냅샷과 분리되어 있어 일정 버전 복원으로 표지가 바뀌지는 않는다.
