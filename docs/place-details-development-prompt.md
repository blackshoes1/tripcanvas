# 장소 상세정보 개발 프롬프트

## 목적
With J에서 지도에 표시된 매장을 눌렀을 때 앱을 떠나지 않고 방문 여부를 판단하게 한다. 기존의 즉시 편집 흐름을 `장소 선택 → 정보 확인 → 명시적으로 일정에 추가`로 바꾼다.

## 이번 구현 범위
정적 웹/PWA의 지도 POI, 검색 결과, 기존 일정에서 공통 장소 상세 패널을 연다. 모바일은 하단 시트, 데스크톱은 상세 패널로 표시한다. iOS 네이티브 화면은 후속 작업이며 이번 웹 구현과 구분한다.

- 해외: 기존 Google Maps JavaScript Places의 Place.fetchFields를 사용한다. 선택한 placeId로만 조회하고 이름·분류·주소·전화·웹사이트·영업시간·평점·평가 수·사진을 제공한다. 리뷰는 사용자가 펼칠 때 조회한다. 필드 마스크로 요청을 제한하고 전체 지도 장소를 선조회하지 않는다.
- 국내: 카카오 검색 결과의 정확한 kakaoId와 주소·전화·분류·상세 URL을 활용한다. 저장된 장소는 검색 결과 ID가 일치할 때만 최신 기본 정보를 연결한다. 사진·평점·영업시간이 공개 API에 없다는 점을 설명한다. Google 콘텐츠를 카카오 지도 위에 혼합하지 않는다.
- 장소 ID가 없는 좌표는 매장으로 단정하지 않는다. 기존 일정의 이름과 원문 검색 링크를 제공하고 자동으로 인근 매장에 연결하지 않는다.
- 패널 열기는 저장하지 않는다. 검색 결과에서는 ‘이 장소 선택’을 눌러야 편집 폼에 반영한다. 닫으면 기존 편집 입력이 유지된다. 기존 일정에서는 상세 확인과 편집을 분리한다.
- ‘가고 싶은 곳’은 기존 협업 보드의 확인 입력으로 연결한다. 로그인/권한 조건을 지키고 기존 작성 중인 후보를 덮어쓰지 않는다.
- 닫기/Escape/키보드 포커스 복귀, 로딩·빈 정보·오류·재시도·늦게 도착한 응답 무시를 구현한다. 읽기 전용에서도 조회할 수 있고 편집 동작은 차단한다.
- 외부 문자열은 textContent, 링크는 안전한 HTTP(S) URL로 처리한다. 사진·리뷰와 제공자 출처를 표시한다. 상세 응답·사진·리뷰는 localStorage/여행 문서/SW에 저장하지 않는다.
- 자동 테스트로 조회만으로 저장되지 않는지, 검색 입력 보존, 비동기 경합, 권한, XSS, 오류 복구를 확인한다. 웹 버전을 올리고 전체 게이트 및 모바일/데스크톱 브라우저 검증 결과를 기록한다.

## 완료 기준
사용자가 지도에서 매장 선택 → 서비스 안에서 정보 확인 → 원하는 날짜에 추가할 수 있다. 카카오 데이터 한계와 실 API 검증 범위를 정직하게 밝힌다. PR 검증 후 배포하며 테스트 작성과 통과를 구분한다.
