# iOS 일정 목록 기본값과 비용 메뉴

일정을 열면 목록을 먼저 표시한다. 지도 전환은 유지한다. 여행 상단의 비용 메뉴에서 여행 전체 예상액, 하루 평균, 날짜별 비용과 카테고리별 원문 내역을 본다.

- 카테고리: 항공, 숙박, 렌트, 대중교통, 식비, 쇼핑, 입장권·관람권, 택시·기타 교통, 기타.
- 날짜를 누르면 기존 하루 비용·예산 입력 화면을 연다. 장소 비용도 카테고리를 명시적으로 바꿀 수 있다. 장소 자체의 분류는 바꾸지 않는다.
- `GET /api/v1/trips/:id/costs`는 기존 여행 읽기 권한과 같은 Gateway를 사용한다. VIEWER는 볼 수 있지만 저장은 할 수 없다. 응답 revision과 문서 revision이 같을 때만 편집한다. 저장은 기존 revision CAS를 그대로 사용한다.
- 판단은 `lib.js`의 `dayCostSummary`, `costCategoryOf`, `tripCostSummary`에 있다. Swift는 합산·예약 배분을 재구현하지 않는다. 일자별 교통비는 기존 경로 캐시와 같은 계산을 사용한다.
- 연결된 장소에 금액이 입력된 예약은 중복 집계하지 않는다. 숙박·렌트 등의 예약은 기존 하루 배분 규칙을 따르고, 여행 날짜에 배분하지 못한 예약 잔액은 별도로 표시하면서 전체·분류별 합계에 포함한다. 전체 합계 = 하루 합계들 + 미배분 금액이다.
- 외화는 기존 기본 참고 환율을 적용한다. 실시간 환율이 아니며 원래 통화·금액·1인 기준·인원과 환산 기준을 표시한다. 무료(0), 미정(null), 일부 금액을 구분하고 미정 교통비는 합계에 들어가지 않았음을 알린다.
- `TRANSIT` 수동 비용은 기존 `TRANSPORT`처럼 하루 자동 교통비를 대신한다. 추가 입력 화면에 이를 설명한다. 기존 비용 문서의 임의 필드는 보존한다.

## 숙박 총액 배분

숙박 비용은 전체 숙박기간의 총액으로 입력한다. 비용 편집에서 숙박일수를 정하면 해당 날짜부터 박 수만큼 하루 비용에 배분하고 체크아웃 날에는 넣지 않는다. 예를 들어 30만 원·3박은 3일에 각각 10만 원이다. 장소 비용과 추가 숙박 비용 모두 같은 규칙을 따른다.

화면에 총액·박 수·해당 날짜 배분액을 표시한다. 나누어떨어지지 않는 금액은 최소 통화 단위로 앞날부터 나머지를 배분한다. 1인 기준은 인원을 적용한 뒤 나누며, 일정 밖으로 남는 숙박비는 미배분 비용으로 전체 합계에 포함한다. 예약과 연결된 비용은 기존 중복 제외 규칙을 유지한다.

## 검증과 배포

순수 계산 테스트, 인증/읽기 전용 API 테스트, 실제 서버 응답과 Swift 계약 정합성 및 XCTest 디코딩 fixture를 검사한다. 수정된 공통 파일은 웹에서도 쓰이므로 서비스워커 버전을 올린다.

NAS에는 새 API가 먼저 필요하다. `docs/nas-release.md`에 따라 migrate·api·realtime을 같은 소스로 빌드하고 전체 서비스를 올린 뒤, 인증된 비용 조회와 일별·분류별 합계, 저장·재조회 권한을 확인한다. 이후 PR 병합과 TestFlight 배포를 진행한다. 서버 문제는 이전 릴리스로 되돌리고, 앱은 이전 TestFlight 빌드로 돌아갈 수 있다. 이번 변경에는 DB 마이그레이션이 없다.
