# 장소 상세 패널 구현 결과

기준 main: `a9c1610`. 브랜치: `feat/place-details`. 웹 버전: `tc-v197`.
요구사항: [개발 프롬프트](place-details-development-prompt.md).

## 구현
- 웹/PWA 지도 POI, 일정 마커·장소명·작업 메뉴, 장소 검색 결과에서 공통 상세 패널을 연다. 모바일 하단 시트/데스크톱 오른쪽 패널이며 native dialog가 포커스·배경 조작을 관리한다.
- Google Place.fetchFields로 이름·주소·분류·전화·웹사이트·영업시간·평점·평가 수·사진을 선택한 장소에 한해 조회한다. 대표 사진 1장을 표시하며 리뷰는 사용자가 펼칠 때 별도 요청한다. Google Maps 및 작성자·원문 출처를 표시한다.
- 카카오 POI·검색의 ID, 주소, 전화, 분류를 활용한다. 저장된 장소는 검색 결과 ID가 같은 것만 연결한다. 제공되지 않는 사진·리뷰·평점·영업시간은 추측하지 않는다.
- 조회만으로 저장하지 않는다. 검색 결과는 ‘이 장소 선택’, 지도는 ‘일정에 추가’ 후 기존 편집기에서 확인·저장한다. 가고 싶은 곳은 이름과 원문 링크를 기존 후보 확인 폼에 채우며 작성 중인 초안을 보존한다. 로그아웃이면 기존 로그인 안내를 제공한다.
- 읽기 전용 조회, 닫기/Escape/포커스 복귀, 오류·재시도, 15초 응답 제한, 늦은 응답 무시, 외부 문자열/링크 방어를 적용한다.
- 사진·평점·리뷰·전화 등의 상세 응답은 여행 문서/localStorage에 저장하지 않는다. 사진 호스트는 서비스 워커 통과 대상에 추가했다. 기존 일정 저장 계약은 그대로 유지한다.

## 검증
전체 `npm run verify:all` 실행 후 필요한 항목을 재검증했다. Windows 로컬 전체 게이트는 PASS가 아니다.

| 검사 | 결과 |
|---|---|
| 구문·웹 버전·lint·tsc·시크릿·의존성 감사 | 통과 |
| 루트 통합 | 128개 통과 |
| 웹 E2E | 초기 54 통과/1 실패: 장소 클릭 후 새 상세창을 닫는 동작이 기존 시나리오에 없었음. 시나리오 보완 및 신규 테스트 포함 전체 57개 통과 |

실제 브라우저와 기존 제한된 공개 SDK 키로 Google 프라도 미술관 상세(사진 실제 로딩, 영업시간, 전화, 평점, 리뷰 5개) 및 카카오 성산일출봉 기본 정보를 확인했다. 모바일 390×844 및 데스크톱 화면을 확인했고 브라우저 page error는 없었다. 실계정 서버 저장은 수행하지 않았다. 자동 테스트는 외부 API를 모형으로 검증하며 전체 공급자 데이터의 완전성을 보증하지 않는다.

## 한계와 배포
- iOS 네이티브 상세 화면, 국내 사진/리뷰 제휴, 메뉴·실시간 예약·대기시간은 이번 범위 밖이다.
- 카카오 바탕 지도의 매장 라벨 자체는 ID를 주지 않으므로 검색으로 직접 올린 POI 칩을 사용한다. ID 없는 좌표를 임의 매장 상세로 매칭하지 않는다.
- Google 정보를 카카오 지도 위에 연결하지 않는다. 국내 Google ID만 있는 저장 장소는 기본 내용과 원문 링크를 제공한다.
- 상세 데이터 요청 필드에 따라 Google 사용량 비용이 발생한다. 지도 전체 선조회나 상세 응답 영구 캐시는 추가하지 않았다.
- PR로 검증하며 main 병합·프로덕션 배포는 별도 단계다. API/DB/NAS 설정 변경은 없다. 되돌릴 때는 커밋을 revert한 후 웹 버전을 다시 올린다.
