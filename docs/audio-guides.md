# 내가 만든 음성 가이드

로그인 후 기기 간 동기화·동행자 공유·공유 파일 오프라인 저장은 [여행 음성 가이드와 티켓·문서](trip-files.md)를 따른다. 아래는 기존 **기기 전용 음성**의 보관 규칙이다.

With J는 음성을 생성하지 않는다. 휴대폰·PC에 준비한 음성 파일을 일정의 장소에 연결하고, 현장에서 직접 눌러 듣는다.

## 사용 방법

- 웹: 장소의 **⋮ → 음성 가이드** 또는 **장소 정보 → 음성 가이드**를 연다. **지금** 화면의 장소에서도 연다.
- **연결할 장소**를 확인하고 음성 파일을 고른다. 한 장소에 여러 파일을 연결할 수 있다. 파일 이름이 이야기 제목으로 표시된다.
- 재생·일시 정지·탐색·음량은 재생 컨트롤로 조절한다. 자동 재생이나 위치 추적은 하지 않는다.
- **음성 삭제**는 확인 후 앱에 저장한 사본과 연결만 지운다. 원본 파일은 남는다.
- iOS: 일정의 장소 상세에서 음성 가이드를 열고 파일 앱에서 가져온다. 지금 화면에서도 같은 장소에 연결된 음성을 연다.

## 저장 범위

- 웹은 전용 IndexedDB `tripcanvas_audio_guides_v1`에 음성 바이트를 저장하고 재생할 때 Blob으로 읽는다. WebKit의 Blob 직접 저장 실패를 피하기 위한 형식이다. 여행 JSON·localStorage·공유 링크·내보내기·서버 동기화에는 파일이나 기기 URL을 넣지 않는다.
- 웹은 현재 계정(로그아웃 상태는 `local`)과 여행, 장소로 구분한다. 계정 전환 시 열린 플레이어를 닫는다. 로그인 전 가져온 파일은 로그아웃 상태에서 다시 보이며 계정으로 자동 이전하지 않는다.
- iOS는 앱의 전용 저장 공간에 파일을 복사하고 계정·여행·장소별로 연결한다. 파일 앱의 원본이 이동해도 가져온 사본은 재생할 수 있다.
- 웹·PWA·iOS 앱·다른 브라우저·다른 기기 간에는 자동 전달하지 않는다. PC에서 준비한 파일을 휴대폰에서 들으려면 휴대폰에도 파일을 전달하고 해당 환경에서 가져온다.
- 저장한 파일은 오프라인에서 재생된다. 웹 앱 자체도 오프라인에서 열려면 온라인 상태에서 앱 셸을 먼저 받아야 한다. iOS 일정은 기존 오프라인 캐시 정책을 따른다.
- 브라우저 데이터 삭제·저장 공간 회수·앱 삭제로 파일이 사라질 수 있다. 원본 파일을 보관한다.

## 장소 연결 규칙

문서에 장소의 영구 ID가 없으므로 Google placeId → Kakao kakaoId → 소수 여섯 자리 좌표 → 도시·이름 순으로 식별한다. 날짜나 목록 번호로 연결하지 않는다. 따라서 정렬·일자 이동 후에도 같은 장소의 음성이 유지되고, 제공자 ID나 좌표가 있는 장소는 이름을 고쳐도 유지된다. 같은 여행에서 같은 장소를 다시 방문하면 같은 음성 목록을 쓴다.

제공자 ID·위치를 바꾸거나, 위치 없는 장소의 도시·이름을 바꾸면 다른 장소로 취급한다. 이 경우 원래 장소 정보로 돌아가면 기존 목록을 다시 볼 수 있다. 장소나 여행을 삭제해도 음성 사본을 즉시 지우지 않아 일정 실행취소를 방해하지 않는다. 불필요한 음성은 장소의 가이드 목록에서 먼저 삭제한다.

## 파일과 검증

파일당 최대 100 MiB. MP3·M4A를 권장하며 WAV·AAC 등 일반 음성 파일도 받는다. 실제 재생 지원은 브라우저·OS 코덱에 따른다. 재생할 수 없으면 오류를 표시하고 변환한 파일을 다시 추가할 수 있다. 비어 있는 파일·명백한 비음성 파일·크기 초과는 저장 전에 거절한다. 저장 공간 부족·저장소 차단·트랜잭션 실패는 성공으로 표시하지 않는다.

웹 회귀 검증: `node --test test/audio-guides.test.js`, `npx playwright test e2e/audio-guides.spec.js --project=chromium`. iOS 검증은 `AudioGuideStoreTests`와 macOS의 기존 전체 게이트를 사용한다. 실기기의 파일 앱·오디오 세션·장시간 재생은 별도 확인한다.
